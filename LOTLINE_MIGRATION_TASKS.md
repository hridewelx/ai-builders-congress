# Lotline — SQL migration tasks

**Date:** 17 November 2026. **No repository and no existing migrations were supplied.** These are **tasks**, not migration files. The reference SQL is `ll01_ll09_spike.sql` (revision 2): it uses a **reduced schema** (integer keys, no `organization_id`, no composite foreign keys, a reduced decision function), so each task must be re-expressed against the real System Design 4 schema. File paths are the System Design 5.1 plan (`backend/alembic/versions/`) and must be checked against the repository.
**Target:** PostgreSQL 18. **Evidence:** the spike passed 39 of 39 checks on PostgreSQL 16.x and 18.7 (`spike_results_pg16.txt`, `spike_results_pg18.txt`). The migrations themselves are NOT TESTED.

**Ordering rule.** Alembic runs as `lotline_owner` only. Run-time roles (`lotline_app`, `lotline_dispatcher`) must not own objects, so every object is created by `lotline_owner` and ownership of definer functions is then transferred to the NOLOGIN writer roles (superuser step in the deploy job, not at run time).
